WORDS YOU WILL SEE
------------------
  Terminal   = the window where you type commands. In VS Code:
               menu  Terminal → New Terminal   (or press  Ctrl + ` )
  Command    = a line you type in the Terminal, then press Enter.
               Only type the part AFTER the "$ " sign.
  Docker     = runs the database for us inside "containers", so we don't
               install Postgres on the Mac itself.
  Volume     = Docker's folder where the database keeps its data. Ours:
                   mom_pg_data   ← database (users, stalls, orders)
                   mom_s3_data   ← uploaded images (menu photos)
  .env file  = small private settings file. Never shared on GitHub.
  Branch/PR  = see CONTRIBUTING.md
  Ctrl + C   = stops a running program in the Terminal.


PART 1 — ONE-TIME SETUP (already done on this Mac ✅)
-----------------------------------------------------
On a NEW computer:
    $ git clone https://github.com/subhankar2004/MOM.git
    $ cd MOM
    $ npm install
    $ npm run setup          (creates the .env settings files and
                              random login secrets for this computer)


PART 2 — EVERY DAY: STARTING
----------------------------
1. Open "Docker Desktop" (Cmd + Space, type Docker, Enter).
   Wait until it says it's running.

2. In the VS Code Terminal:
    $ cd /Users/subhankarpatra/Developer/myWorkSpace/MOM
    $ git switch main
    $ git pull               (gets the latest merged work)
    $ npm install            (only needed if someone changed packages)
    $ npm run db:up          (starts database + image storage)
    $ npm run db:migrate     (applies any new database changes)

   It finishes with "Healthy" for mom_postgres and mom_s3. ✅

   Make yourself SUPER ADMIN (once): open apps/api/.env, put your mobile
   number after  SUPER_ADMIN_PHONES=  (e.g. SUPER_ADMIN_PHONES=9876543210),
   save, then run   $ npm run db:seed

3. Start the API (and, from issue #6, the website):
    $ npm run dev
   API:      http://localhost:4000/health   → {"status":"ok",...}
   API docs: http://localhost:4000/docs     (every endpoint, try them out)
   Website:  http://localhost:3000
   Stall owner area:  http://localhost:3000/vendor
   Admin area:        http://localhost:3000/admin
   Style guide:       http://localhost:3000/dev/components
                      (every button, card and colour in one page;
                       the round button top-right switches light/dark)
   Stop it with  Ctrl + C.

   Login codes (OTP) are NOT sent by SMS on your Mac — they are printed
   in this Terminal, in a line starting with  📱 SMS (not really sent).
   To sign in: open http://localhost:3000/login, type your number,
   copy the 6-digit code from this Terminal into the boxes.
   Your number is in SUPER_ADMIN_PHONES (apps/api/.env), so you land
   on the admin area (/admin). Any other number becomes a student.

   Make a number a STALL OWNER (until the admin screens arrive in #23):
   API docs http://localhost:4000/docs (signed in as you, the admin) →
   "vendor" → GET /v1/vendor/stalls → copy a stall's "id" → "admin" →
   POST /v1/admin/stalls/{stallId}/members with {"phone": "98765 43210"}.
   That number signs in at /login and lands on its stall console.


PART 3 — CLOSING FOR THE DAY
----------------------------
1. In the Terminal running "npm run dev":  press  Ctrl + C
2. $ npm run db:down       (stops the database — your data is KEPT)
3. Quit Docker Desktop (whale icon in the menu bar → Quit).


PART 4 — USEFUL COMMANDS
------------------------
(run from  /Users/subhankarpatra/Developer/myWorkSpace/MOM )

  npm run db:up        start database + storage
  npm run db:down      stop them (data kept)
  npm run db:reset     ⚠ ERASE all local data, rebuild the tables and
                       re-add the 4 demo stalls with their menus
  npm run db:migrate   apply new database changes (after git pull)
  npm run db:seed      add default fees, super admins, demo stalls
                       (safe to run again — it never duplicates)
  npm run db:psql      open a database prompt (type  \q  to leave)
  npm run db:logs      watch what the database is doing (Ctrl + C to stop)
  npm run env:check    check the API settings file is valid
  npm run check        format + lint + typecheck + tests (must pass before a PR)
  npm test             only the quick tests
  npm run test:int     database tests (needs  npm run db:up  first)

  ⚠ Don't delete the mom_pg_data / mom_s3_data volumes in Docker
    Desktop unless you want to erase all local data.


PART 4b — TRYING ONLINE PAYMENTS (Razorpay TEST mode, no real money)
-------------------------------------------------------------------
Your test keys are already in apps/api/.env. To pay for an order:
  1. Order from an OPEN stall, choose "Pay now by UPI", tap Place order.
  2. The Razorpay window opens. In test mode use one of:
       • Netbanking → any bank → on the next page click "Success"
       • Card 4111 1111 1111 1111, any future expiry, any CVV,
         then "Success" on the test page
       • UPI id  success@razorpay  (only if UPI is switched on for your
         Razorpay account: Dashboard → Account & Settings → Payment methods)
  3. Your token number appears on the order page.

Optional — Razorpay calling your Mac directly (the "webhook", which
confirms payments even if the browser is closed):
    $ npx cloudflared tunnel --url http://localhost:4000
  It prints an https://….trycloudflare.com address. In the Razorpay
  dashboard (Test Mode) → Settings → Webhooks → Add:
    URL:    https://….trycloudflare.com/v1/webhooks/razorpay
    Secret: the RAZORPAY_WEBHOOK_SECRET value from apps/api/.env
    Events: payment.captured, order.paid, payment.failed


PART 5 — COMMON PROBLEMS
------------------------
"Cannot connect to the Docker daemon" / db:up fails
    → Docker Desktop isn't running. Open it, wait, try again.

"port is already allocated" / "address already in use" on db:up
    → Something else uses port 5432 or 8333. Create a file named  .env
      in the MOM folder (copy .env.example) and change POSTGRES_PORT
      or S3_PORT — then also change the port in apps/api/.env .

"Invalid environment configuration" when running env:check or dev
    → It lists which setting in apps/api/.env is wrong. To start over:
      delete apps/api/.env and run  npm run setup .

Anything else → copy the red error text and ask Claude. 🙂
